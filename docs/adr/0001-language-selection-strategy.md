# ADR-0001: 语言选型策略

## 背景

游戏引擎需要同时处理两类截然不同的编程任务：

**底层系统编程**：
- 平台抽象（窗口、输入、文件 I/O）
- 内存管理（allocator、arena、pool）
- 硬件接口（GPU 命令提交、音频设备）
- 与操作系统和 C 生态的深度互操作

**高层逻辑编程**：
- 游戏世界模型（实体、组件、系统）
- 任务调度与并发
- 游戏逻辑与状态管理
- 复杂的业务规则与正确性保证

单一语言难以在两个维度都达到最优：
- C/C++ 在底层有优势，但高层逻辑的安全性和表达力不足
- Rust 的所有权系统适合逻辑层，但在底层系统编程时与借用检查器的摩擦较大
- Zig 在底层系统编程和 C 互操作上极其自然，但缺乏高层抽象能力

项目的首要目标是**学习与能力提升**，次要目标是做出可玩游戏。多语言策略可以在两个维度都获得深度学习价值，代价是工程复杂度上升。

---

## 决策

### 1. 采用 Zig + Rust 双语言策略

引擎采用 Zig 和 Rust 两种语言实现，按模块特性分工。

#### Zig 负责的模块类型

- **平台抽象层**（窗口、输入、时钟、文件 I/O）
- **内存管理**（allocator、arena、pool）
- **渲染硬件接口**（RHI，GPU 命令提交）
- **所有需要导出 C ABI 的模块**（作为跨语言边界）

**理由**：
- Zig 的 `comptime` 和显式内存管理适合底层系统编程
- Zig 与 C ABI 的互操作几乎零成本
- Zig 的错误处理和可选类型比 C 安全，但比 Rust 更轻量
- 平台层代码通常需要直接调用操作系统 API，Zig 的 `@cImport` 可以直接使用 C 头文件

#### Rust 负责的模块类型

- **世界模型**（实体存储、组件管理、更新调度）
- **任务调度系统**（异步任务、线程池）
- **游戏逻辑层**（碰撞、AI、游戏规则）
- **状态复杂、正确性要求高的模块**

**理由**：
- Rust 的所有权系统天然适合管理实体生命周期
- Rust 的类型系统和 trait 抽象适合表达复杂的游戏逻辑
- Rust 的 `Result` 和 `Option` 强制错误处理，减少运行时崩溃
- Rust 的生态（如 `rayon`、`tokio`）在并发和异步任务上成熟

---

### 2. 跨语言边界约束

#### 硬性规则

1. **所有跨语言调用必须通过 C ABI**
   - Zig 模块导出 `extern "C"` 函数
   - Rust 模块通过 `extern "C"` 调用 Zig 函数
   - 禁止直接使用语言特定的 FFI 机制（如 Rust 的 `#[repr(Rust)]`）

2. **禁止直接传递语言特定类型**
   - 不允许：Rust 的 `Vec`、`String`、`Box`、`&str`
   - 不允许：Zig 的切片 `[]T`、`ArrayList`、`HashMap`
   - 不允许：闭包、trait object、函数指针（除非符合 C 调用约定）

3. **每个跨语言边界必须有对应的 C 头文件**
   - 所有跨语言接口在 `abi/` 目录下定义
   - C 头文件是接口契约的单一真相来源
   - Rust 侧使用 `bindgen` 自动生成绑定，不手动维护

#### 边界数据类型规范

详细规范见 **ADR-0003: 跨语言边界规范**（必须在首个跨语言调用前完成）。

基本原则：
- **字符串**: C 风格 null-terminated `const char*`
- **数组**: 指针 + 长度（`const T* data, size_t len`）
- **错误**: 统一的 C 风格错误码（`int32_t`，0 表示成功）
- **内存**: 调用方分配，被调用方使用，调用方释放（或使用传入的 allocator）
- **不透明句柄**: 用 `void*` 传递，内部类型对调用方不可见

### 3. 语言选择原则

新增模块时按以下原则选择语言：

| 模块特征 | 推荐语言 | 理由 |
|---|---|---|
| 直接调用操作系统 API | Zig | `@cImport` 直接使用 C 头文件 |
| 需要导出 C ABI 给其他模块 | Zig | Zig 的 `extern` 导出更自然 |
| 性能关键且需要手动内存控制 | Zig | 显式 allocator，无隐式分配 |
| 复杂状态管理 | Rust | 所有权系统防止状态泄漏 |
| 需要强类型保证的业务逻辑 | Rust | 类型系统 + trait 抽象 |
| 与 Rust 生态库深度集成 | Rust | 避免重复造轮子 |

**例外情况**：
- 如果某个模块的特征同时符合两侧，**优先选择 Zig**（因为 Zig 导出 C ABI 更自然，可以被 Rust 调用）
- 如果某个模块需要频繁跨语言调用，**重新审视模块边界**，考虑合并到单一语言侧

---

### 4. 禁止事项

1. **禁止为了"方便"而随意跨语言调用**
   - 每个跨语言边界都是潜在的性能和安全风险点
   - 必须有明确的架构理由（如"平台层必须用 Zig，游戏逻辑必须用 Rust"）
   - 不允许"这个函数用 Rust 写更方便"这种理由

2. **禁止在跨语言边界传递复杂类型**
   - 不允许传递嵌套结构体、联合体、枚举（除非在 C 头文件中显式定义）
   - 不允许传递包含指针的结构体（除非指针语义在 C 头文件中明确定义）

3. **禁止在 ADR-0003 完成前新增跨语言调用**
   - 跨语言边界规范必须先定义
   - 包括：字符串、错误、内存、所有权、panic 语义
   - 否则第一个跨语言调用就会遇到无法解决的问题

4. **禁止引入第三种语言（C/C++）作为实现语言**
   - C/C++ 只能作为第三方库的依赖（如 SDL、OpenGL 加载器）
   - 引擎自身代码只使用 Zig 和 Rust
   - 理由：三种语言的构建系统集成复杂度过高

## 后果

### 正面影响

1. **学习价值最大化**
   - Zig：学习底层系统编程、显式内存管理、C 互操作、comptime 元编程
   - Rust：学习所有权系统、类型系统、trait 抽象、并发安全

2. **技术适配性**
   - Zig 处理底层时的显式控制和 C 互操作优势
   - Rust 处理逻辑时的类型安全和所有权保证
   - 两种语言的优势在各自擅长的领域发挥

3. **架构纪律**
   - 跨语言边界强制模块边界清晰
   - 不能随意跨边界调用，倒逼良好的接口设计

### 负面影响

1. **构建系统复杂度上升**
   - 需要同时编排 Zig 和 Rust 的编译
   - 需要处理两种语言的依赖管理
   - 增量编译的粒度变粗

2. **跨语言调试困难**
   - 调试器跨语言边界时可能丢失上下文
   - 错误堆栈跨越两种语言时难以追踪
   - 需要熟悉两种语言的调试工具

3. **每个跨语言边界都是风险点**
   - 类型不匹配可能导致 UB
   - 内存所有权不清晰可能导致泄漏或 double-free
   - 错误传播不一致可能导致 panic

4. **新贡献者门槛提高**
   - 需要熟悉两种语言
   - 需要理解跨语言边界的约束
   - 开源后可能降低社区贡献意愿

### 缓解措施

1. **严格限制跨语言边界数量**
   - 目标：不超过 **5 个主要边界**
   - 当前规划：platform、mem、rhi 导出 C ABI，Rust 侧调用
   - 每增加一个边界都需要架构评审

2. **所有边界必须有清晰的 C 头文件定义**
   - `abi/` 目录是接口契约的单一真相来源
   - 修改 `abi/*.h` 需要同步更新两侧实现
   - 使用 `bindgen` 自动生成 Rust 绑定，减少手动维护

3. **优先在单一语言内部解决问题**
   - 跨语言调用是最后手段
   - 如果某个功能可以在单一语言内实现，不要为了"方便"跨语言
   - 例如：Rust 侧需要分配内存，优先用 Rust 的 `Box`/`Vec`，而不是调用 Zig 的 allocator

4. **建立跨语言调试工具链**
   - 统一的日志系统（跨语言可见）
   - 统一的错误码定义
   - 跨语言边界的输入输出日志

## 备注

### 为什么不选 C/C++

- **C**: 缺乏高层抽象能力，错误处理和内存安全完全依赖纪律
- **C++**: 现代 C++ 的复杂度过高，构建系统（CMake）是额外负担，且与 Rust 的互操作不如 C ABI 自然

### 为什么不选单一语言

- **纯 Zig**: 高层逻辑的类型系统和抽象能力不足，缺乏成熟的并发库
- **纯 Rust**: 底层系统编程时与借用检查器的摩擦较大，C 互操作需要 `unsafe` 和 `bindgen`

### 首期模块映射

| 模块 | 语言 | 理由 |
|---|---|---|
| platform | Zig | 直接调用 Win32/X11 API |
| mem | Zig | 显式 allocator，导出 C ABI |
| rhi | Zig | GPU 命令提交，导出 C ABI |
| world | Rust | 实体生命周期管理 |
| scheduler | Rust | 异步任务与并发 |
